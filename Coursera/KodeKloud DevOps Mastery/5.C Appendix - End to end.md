# 5.C

## Steps
1. Create deployment or pod YAML
2. Create service YAML
3. Apply the YAMLs
    - `kubectl apply -f deployment.yaml`
    - `kubectl apply -f service.yaml`
4. Validate results
    - `kubectl get deployments`
    - `kubectl get services`

## Design Consideration

### Storage of YAML files
- Organized in a version-controlled repository
- Create folders for `dev`, `staging` and `prod`
    - or put them in `manifests`
- Use `base` as template and `overlay` to add changes
- Group by resource type like `deployment`, `service` and `configmap`

### Contiuous Deployment
- CI/CD pipelne with GitHub Actions
```yaml
name: Deploy to Kubernetes

on:
  push:
    branches:
      - main  # Or your specific deployment branch

jobs:
  deploy:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v2

      - name: Set up kubectl
        uses: azure/setup-kubectl@v2
        with:
          version: 'latest'

      - name: Authenticate with Kubernetes
        env:
          KUBECONFIG: ${{ secrets.KUBECONFIG }}  # Set up a KUBECONFIG secret in GitHub
        run: |
          echo "$KUBECONFIG" > ~/.kube/config

      - name: Apply Kubernetes manifests
        run: |
          kubectl apply -f k8s-configs/  # Specify the directory of YAMLs
```

- ArgoCD
```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-app
  namespace: argocd
spec:
  project: default
  source:
    repoURL: 'https://github.com/your-org/your-repo.git'
    targetRevision: main  # Branch name
    path: k8s-configs      # Directory with YAML files
  destination:
    server: 'https://kubernetes.default.svc'
    namespace: default
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
```
