# 5.5

## Services
- Ways to expose a pod to outside
- Connect applications together
- Enables connectivity between pods
- Loose coupling

> A service forward the requests to ports on nodes to pods

> If multiple pods are on single node, loadbalancing is done automatically

|`kind`|Purpose|Use Case|Principle|
|-|-|-|-|
|`ClusterIP`    |Expose service on internal IP within cluster     |Internal communication between components||
|`NodePort`     |Exposes service on each node at `port`           |Expose application outside cluster||
|`LoadBalancer` |Expose service by cloud load balancer            |||
|`ExternalName` |                                                 |||
|`Ingress`      |Manage external access to services via HTTP/HTTPS|Expose multiple serice under single domain, perform URL-based routing|Ingress controller like Nginx or Traefik manages routing rules|
|Headless       |Direct communication with individual pod IPs without load balancer|Stateful application where IP is required|`clusterIP: None`|

### Steps
1. Create deployment to spawn the pods
2. Create service to forward traffic to pods
3. Apply the YAMLs

## Types of Services

### NodePort

> Exposes port on each node where pods run

#### Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: example-nodeport-service
  namespace: default  # Specify the namespace if needed
spec:
  type: NodePort
  selector:                    # Apply by labels
    app: example-app
  ports:
    - port: 80                 # The port on the service
      targetPort: 8080         # The port on the container
      nodePort: 30007          # The port exposed on each node (between 30000-32767)
```

### ClusterIP

- Creates an IP which other service can reach by
- `<service-name>.<namespace>.svc.cluster.local`

#### Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: example-clusterip-service
  namespace: default  # Specify the namespace if needed
spec:
  type: ClusterIP
  selector:
    app: example-app
  ports:
    - port: 80               # The port on the service
      targetPort: 8080       # The port on the container
```

### ExternalName

#### Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: example-externalname-service
  namespace: default  # Specify the namespace if needed
spec:
  type: ExternalName
  externalName: external.example.com
```

### LoadBalancer

#### Example
```yaml
apiVersion: v1
kind: Service
metadata:
  name: example-loadbalancer-service
  namespace: default  # Specify the namespace if needed
spec:
  type: LoadBalancer
  selector:
    app: example-app
  ports:
    - port: 80               # The port on the service
      targetPort: 8080       # The port on the container
      protocol: TCP
```

## Exposing Deployments

```bash
kubectl expose deployment <deployment-name> --type=ClusterIP --port=<port> --target-port=<container-port>
```

```bash
kubectl expose deployment <deployment-name> --type=NodePort --port=<port> --target-port=<container-port>
```

```bash
kubectl expose deployment <deployment-name> --type=LoadBalancer --port=<port> --target-port=<container-port>
```

```bash
kubectl create service externalname <service-name> --external-name=<external-domain>
```

```bash
kubectl port-forward deployment/<deployment-name> <local-port>:<container-port>
```
