# 5.5

## Services
- Ways to expose a pod to outside
- Connect applications together
- Enables connectivity between pods
- Loose coupling

|`kind`|Purpose|Use Case|Principle|
|-|-|-|-|
|`ClusterIP`|Expose service on internal IP within cluster|Internal communication between components||
|`NodePort`|Exposes service on each node at `port`|Expose application outside cluster||
|`LoadBalancer`|Expose service by cloud load balancer|||
|`ExternalName`||||
|`Ingress`|manage external access to services via HTTP/HTTPS|Expose multiple serice under single domain, perform URL-based routing|Ingress controller like Nginx or Traefik manages routing rules|
|Headless|Direct communication with individual pod IPs without load balancer|Stateful application where IP is required|`clusterIP: None`|

## Exposing Deployments

```bash
kubectl expose deployment <deployment-name> --type=ClusterIP --port=<port> --target-port=<container-port>
```

```bash
kubectl expose deployment <deployment-name> --type=NodePort --port=<port> --target-port=<container-port>
```

```bash
kubectl expose deployment <deployment-name> --type=LoadBalancer --port=<port> --target-port=<container-port>
```

```bash
kubectl create service externalname <service-name> --external-name=<external-domain>
```

```bash
kubectl port-forward deployment/<deployment-name> <local-port>:<container-port>
```
